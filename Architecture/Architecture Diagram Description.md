# Architecture Diagram
This diagram descripe the main components of the SIP application, and how these components interact with each other.

The core components is the SIP app that has the UI, mainly interact with the backend to perform its logics, sendand retrieve data.
Next we have the backend powerd by Supabase platform which perform diverce services, including:
1. Authentication Service: it perform authenticatio services such as: Sign up, Login and Resetting the password and insure a scure access to the user acccounts and data.
2. Logic: it perform the bussiness logic including the system boundery, the system behaviour and how the system should react.
3. Image/File Storage Service: Stores locally the app images and files.
4. Date Processing: Fetch the raw data and converted it to an structured form that is acceptable by the database.

Now moveing to the database service by PostgreSQL, which cover the following services:
1. Secure a persistent storage for the user data.
2. Define the main structure of the database (primary and forign keys, data types).
3. Send and fetch structured data from the backend.
4. Fetch the prediction results.

Next we have the AI model that will recive the CGM reading, carb inputs and any related information from the database and send the prediction results back to the database.

1. AI Model:The model retrieves CGM readings, carbohydrate inputs, and other relevant information from the PostgreSQL database through the backend. These data are then processed using algorithms to predict blood glucose trends and recommend appropriate insulin doses. Finally, the prediction results are stored back in the database to be used by the system logic, whether for displaying recommendations within the SIP application, supporting decision-making processes, or triggering alerts in addition, emergency actions when required.
2. API Services:
   *Notification Service API: Is responsible for delivering real time alerts and notifications to the user’s device based on system events and AI model outputs. It is used to inform users about critical blood glucose conditions, such as high or low glucose levels, as well as insulin dose recommendations generated by the system.
   *Emergency Service API: Acts as an additional safety layer within the system and is activated only in critical situations. When dangerous glucose readings are detected or when the user fails to respond, the system automatically triggers predefined emergency procedures and sends urgent alerts to designated contacts or emergency services.
3. Insulin Pump Hardware Integration: Enables direct and controlled communication between the system backend and the insulin pump device. Through dedicated communication interfaces, the backend sends insulin dose execution commands to the pump and receives execution confirmations or error messages in return. All pump-related actions are recorded in the database to ensure traceability, monitoring, and safe system operation.
